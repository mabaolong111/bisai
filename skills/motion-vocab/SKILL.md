# motion-vocab · 动效词汇台

## 这是什么

AI 不缺实现能力，缺能解码的名词。本 Skill 做三件事：**把看到的东西翻译成名词**、**把名词攒成资产**、**用资产守住设计下限**。

公式：**名词定种类，参照定刻度；形容词只用来否定。**

---

## 〇、先判模式（每次开工第一件事）

| 用户说的话 | 模式 | 读哪份 | 交付物 |
|---|---|---|---|
| "帮我拆解这个项目 / 这条视频 / 这些动效叫什么 / 它怎么实现的" | **A 拆解（主线）** | `references/teardown.md` | 六栏拆解表 |
| "我想了解 **滚动驱动 / 版式 / 纵深 / 风格** 这块有哪些做法、有哪些案例" | **B 领域（横评线）** | `references/survey.md` | 横评稿 → 领域册 |
| "把这个主题做成一册 / 讲清楚这册" | **A′ 立册** | `teardown.md` 或 `survey.md` + `references/booklet.md` | 一册单页 HTML |
| "给我做个页面 / 改改这页 / 太素了" | **C 设计（副线）** | `references/intent.md` + `words.md` | 页面 + 五条验收 |
| "这叫什么 / 参数多少 / 在哪一册" | **查词** | `references/words.md` | 一句话 + 册号 + 区间 |

**A 与 B 的区别只有一句**：拆解是"**一个项目**怎么做到的"，领域是"**同一件事有几种做法、哪种更划算**"。

- A 的输入是**别人的一个东西**（仓库 / 站点 / 视频），有源码兜底，参数追到行号；
- B 的输入是**一个主题词**，没有源码兜底，靠 ≥5 个可核来源的证据链（门槛见 `survey.md` §二，凑不齐就别立册）；
- A 的原稿叫 `<项目名>·拆解.md`，B 的原稿叫 `综述\<主题>\横评.md`——**两个目录平行，不许混放**。

**顺序不许反：A 与 B 进货，C 出货。** 词库里没有的东西，不要在设计阶段现编——先拆一个回来，或先扫一个主题回来。

判断依据：用户给的是**别人的东西**（项目、站点、视频、截图）→ A；给的是**一个主题词**（"滚动驱动有哪些做法"）→ B；给的是**自己的需求**（要做什么页）→ C。

**短指令默认行为（重要）**：用户只说了"拆解这个项目 / 这条视频"这种一句话时，按这个默认跑，不要反问一串问题：

1. 走模式 A，先按 `teardown.md` 出**六栏表**（结构照旧，但落盘文件名是 `<项目名>·拆解.md`，**不许再叫 `六栏.md`**）；其中 **2·补「模块全量清单」不许省**——它有 19 个模块就写 19 个，名字用项目自己的官方叫法（组件用设计规范正式名、面板用代码里的面板名），写不出全量说明还没拆完，不是"它没有"；
2. 出完表**停住**，问一句"要不要按 booklet.md 立成一册"——**不要直接开始写 HTML**。这里说的"取舍"只发生在册子上（一册 12 词、只取一条轴），**拆解稿永远全量**；
3. 用户说"要 / 继续 / 做成册吧"→ 立册。**立册前先做三件事，一件都不许跳**：
   - **查重**：读 `<项目目录>\booklets/索引.md`，报得出"这册与已有 13 册的分工"；
   - **取词**：12 词只能从原稿第 4、5 栏出，不许另编；
   - **换轴**：若booklets里已有同项目 / 同手法的册子（如 `案例拆解·神经创作面板`），**必须换一条新轴**，只留别人没写过的条目，并在 §01 写一句"这册和 X 册谁管什么"。
   - **先定名**：动笔前给三个候选名，每个 ≤6 字、名词+主题（如 `预渲染首屏词汇册`），等用户挑一个再写 §01。**不许边写边起名**——文件名是主题断言，主题是拆出来的，不是想出来的；五个名词叠一起（"预渲染素材首屏词汇册"）就是没定名。
4. **立册的固定规格**（写在 `booklet.md`，此处只列会被漏掉的四条）：一册**只装 12 词**；§08 每词标"册号 + 轴"；§10 给**四条边界**；页脚抄原稿第一章的 LICENSE 与商用结论（PolyForm / 无 LICENSE = 只当参考书，mp4 与代码片段都不进产出）。
5. 交付前跑 `run_all.py`，五项全绿才算完（**必须传 `--deny-file`**，隐私项才真的扫产出目录；不传就只有四项，末行会写「隐私未检查」）。

**走领域线（B）时**：不要拆一个项目就下结论。按 `survey.md` 先取证——≥5 个可核来源、≥2 个真分歧点、≥1 个当场跑通，凑不齐就**不立册**，把已有条目写进索引的"待验清单"并说明缺哪几条。原稿落 `综述\<主题>\横评.md`。

**落盘必须自证**：写完原稿或成品后，当场回报"绝对路径 + 字节数 + 首行原文"三样（细则见 `teardown.md` §七）。只说"已保存到…"、或只在聊天里贴一份 Markdown 预览，**都按没落盘处理**。

**一句话也要跑通（本 Skill 的验收题）**：用户只说"拆这个项目"或"做成册吧"，以上三步全部默认执行，**不许回头追问**。若没指定项目，自己去项目目录下找最近改动的 `拆解\<项目名>\<项目名>·拆解.md`，把它所在的目录当 `<项目目录>`。允许的唯一提问只有一处——六栏出完后那句"要不要立册"。

**注意 6 秒与 6 分钟的区别**：解析指代是读两个文件的事，不是问用户的事。**先读，再问**；读到了就不用问。一个合格的回复应在前 10 秒内已经打开那份拆解稿或横评稿。

**规格不许靠用户补**：一册 12 词、四条边界、页脚许可、12 词标册号、`run_all.py` 五项、落盘三证，全部由本 Skill 自带。用户提示词里出现这些，说明本 Skill 没写对，要回来改这里，不是让用户照着念。

**空指代怎么解码（真实用户不点名对象，只说"这个 / 那种效果 / 接着做"）**：按"最近优先"解码，解完**先用一句话声明再动手**，不要反问：

| 用户说的 | 解码成 |
|---|---|
| "这个项目 / 这个东西" | 上下文里最近出现的项目名或路径 |
| "这个 / 这份 / 按 Skill 里说的做 / 接着做" | 最近落盘的 `拆解\<项目名>\<项目名>·拆解.md`，它上一级目录即 `<项目目录>` |
| "那种效果 / 跟之前一样" | 最近一次交付的册子的版式与密度（纸、强调色、十节骨架照旧） |
| "按这个 Skill" | 就指本 Skill，不需要用户点名 |

声明句式固定三短句：**"我按 `<对象>` 做；取的是 `<绝对路径>`；规格照 `booklet.md` 的十节。"** 声明完直接做，不等确认。

**只有候选 ≥2 个时**（目录里有两份拆解稿、或上下文里有两个项目）才许问一句，问法也只给编号："A 是 x，B 是 y，做哪个——还是两个都做？" 不许问"你想让我做什么"。

**指代先解析，别先澄清（这条最容易翻车）**：用户说"这个 / 它 / 刚才那个 / 那种效果 / 做成册吧"时，"这个"不是空话，是有落点的。按顺序找，找到就动手：

1. 本会话上文刚出的六栏表或文件 → 直接接着做；
2. `<项目目录>\拆解\` 下最近改动的 `<项目名>·拆解.md` → 把它当原稿，直接立册；
3. `<项目目录>\booklets/索引.md` 里的"待拆清单" → 按第一条开始拆；
4. 以上全空，才问一句"要拆哪个项目 / 要做哪一册"。

**不许出现的情况**：用户说完一句"按 Skill 里说的做成那种效果"，先回一段"明确用户具体需求"或列三五个问题清单——这是把解析工作丢回给用户，属于本 Skill 不合格。

只有当输入根本无法判断（没给对象、只给了截图里一帧）时，才问那一个必需的问题。

## 一、七步开工顺序（C 设计线用；A 走 `teardown.md`、B 走 `survey.md`）

1. **定用途**：给谁看 / 在哪看 / 大概几屏。
2. **定"纸"与强调色**：六张纸选一张（网格 / 走线 / 坐标 / 暗场 / 纸感 / 纯白），强调色 ≤2，且只用于"数据 / 当前态 / 路径"。
3. **定版式框架**：按项目类型选骨架（见 `references/words.md` 第 3 册），**先版本式，再选动效**。
4. **选词**：≤3 类，先查 `references/words.md`，报词必须带"册号 + 轴"。
5. **定参数区间**：给范围不给死值（区间从 `words.md` §3 抄）。
6. **定实现**：原生 → CSS → 库，够用就停（判定见 §七末）。
7. **报验收**：读哪几个数、移动端怎么算过、`reduced-motion` 停在哪。

**前 3 步没落地，不许动笔写代码。** 这一步是防止"每册各取一个堆在首页"的唯一闸门。

开工前把这 1–4 步填进 `references/intent.md`（设计意图单，七行），填完再写。

**读不到意图单时**（文件缺失或无权限）：不要跳过，也不要替用户编——直接在对话里把七项逐个问清（用途 / 承诺 / 纸 / 色 / 主角 / 三类词 / 验收），问齐了再动手。

## 二、路由表（任务 → 读哪几份，按需读，不要全读）

册子本体放**用户自己的项目目录**里，不进本 Skill（体量太大，只按路径去翻）。册目与待拆清单见 `<项目目录>\booklets/索引.md`。

**编号规则（最容易错的一条）**：册号由**项目内的 `索引.md`** 分配，`01` 起连续，一册一个号，**空号不补**。

- 用户项目里没有 `索引.md` → **这本就是 01**，不要因为看到了下面那张示例表，就给自己起 13 号；
- 有 `索引.md` → 读它，取最大号 +1；
- **编号必须露在读者看得见的地方，一共三处**：① **文件名前缀**（`16-响应词汇册.html`）；② **`h1` 前缀**（`第 16 册 · 响应词汇册`）；③ **页脚**（有册链的，首格写 `16` 不写"本册"；没册链的，就在页脚上方加一行 `<p class="bkno">第 16 册 · 主题</p>`）。**编号只是前缀，主题不许省**——`16-响应词汇册` 对，`16.html`、`第16册.html` 都不对；
- 编号一旦分配不再改，空号不补；册内引用别册（§08 表的「册号+轴」列、页脚册链）用同一套号，不许另起一套。

下面是**原作者项目**的册目，只用来告诉你"这套方法能拆出多少条轴"，**不是你的编号，也不许照抄成你的册目**：

```
（原作者示例，仅供参照词汇覆盖范围）
鼠标 · 3D纵深 · 版式与组件 · 风格与视觉语言 · 画布型页面 · 质感与滚动
滚动驱动 · 结构型滚动 · 群体光标 · 编排 · 物理与弹性 · 路径与轨道 · 预渲染首屏
```

**成品样例只有两册**（都是原作者自产、零第三方素材、零第三方行号，可随 Skill 分发）：

| 样例 | 示范什么 | 读法 |
|---|---|---|
| `assets/样例-03-版式与组件词汇册.html`（23.5 KB） | **框架类产物**：不拆别人的项目，从零建骨架词（14 骨架 / 16 零件 / 刻度）——这是"没项目可拆时"的做法 | 通读可接受，它是轻的那本；**可当立册的起步骨架直接复制改词**（版式、术语卡四段、演示读数、页脚都齐），但它只有 3 个 section，离十节册还差 7 节，补完 §08 速查 / §09 五槽位 / §10 边界才能跑 `--section 10` |

**拆解的三条纪律**（细则在 `references/teardown.md`）：

- 形容词不许进报告——"高级、丝滑"出现即视为这一栏没写；
- `实测` 与 `估` 必须分栏；视频来源一律标"估"并写推算依据；
- 无 LICENSE 的项目只当参考书，代码连片段都不进商用产出。

## 三、五槽位（写提示词就照这五行）

1. **对象与层**（谁是主角、在哪一层：风格层 / 组件层 / 动效层不能混说）
2. **效果名**（中文 + 英文双写，让模型认得出）
3. **参数区间**（给范围，不给"好看一点"）
4. **实现约束**（CSS 能不能干、要不要库、能不能上合成器）
5. **验收**（读哪个数、多少算过）

例：`首屏右侧折线 → 滚动进度映射 scroll-driven progress mapping → 0–100%，阻尼 0.4–0.8s → 原生 CSS scroll-timeline，退化用 IntersectionObserver → 读数差值 ≤3%`

---

## 四、八条判据（"高级感"的可核对版）

1. **留白是比例不是感觉**：间距取 64/96/144 一组，不随手 80px。
2. **色受限**：一套中性灰阶 + ≤2 强调色；强调色只出现在含义上，不做装饰。
3. **字体分工**：衬线标题 / 等宽数据 / 无衬线正文；字号只允许五档。
4. **一页一张能自我解释的"纸"**：写不出"它为什么解释这个题材"，就是贴上去的。
5. **一屏一个会动的主角**，其余 settle。
6. **动效只有三档时长、三档缓动**，不许每条自创。
7. **微交互确定性**：hover 有反馈不变形；点击有回弹不过冲（≤8%）。
8. **细节密度是真的**：真实读数、真实数字，不用占位图与 lorem。

## 五、五条禁止样式（出现即掉质感）

1. 暖奶油底 + 陶土橘标题（最常见的"AI 温柔风"）；
2. 近黑底 + 酸性绿 / 朱红点缀（假科技感）；
3. 大报式零圆角满分栏 + 密集小字（假杂志感）；
4. 一堆同一种阴影的圆角白卡（假 SaaS）；
5. 模板化外壳：全大写眉标 + 中点串元信息 + 标题后缀 `→`。

排掉这五条之后，造型只能由题材自己长出来——这是唯一稳的路。

## 六、验收（一条总命令，或单跑某几项）

**`{file}` 是占位符，必须替换成真实路径再运行；整条路径要加双引号。不要照抄带花括号的命令。**

**跑之前先装依赖**（只有溢出项需要它）：`python -m pip install playwright`。脚本会优先用本机 Edge（`channel='msedge'`）免下载浏览器，没有 Edge 就回退到已装 Chromium。没装 playwright 时，溢出项会打印 `SKIP 依赖 playwright 未安装…` 并返回退出码 3，这是"环境未就绪"，**不是页面溢出的失败**。

```bash
python scripts/run_all.py "{file}" --section 10 --deny-file "{本机禁词文件}" [--target-dir "{产出物目录}"]
```

传了 `--deny-file` 时跑五项（结构 → JS 语法 → 样式 → 溢出 → 隐私），全绿才打印 `5/5 通过`；不传时只跑四项，末行明确写「隐私未检查」，不假装通过。隐私项默认扫**被测文件所在目录**（也就是产出物目录），不是 Skill 自己；要扫别处就加 `--target-dir`。只想知道某一项时，单跑：

```bash
python scripts/check_struct.py   "{file}" --section 10
python scripts/check_js.py       "{file}"
python scripts/check_style.py    "{file}"
python scripts/check_overflow.py "{file}" --width 390 --wait 800
python scripts/check_privacy.py  "{dir}" --deny-file "{本机禁词文件}"
```

例（仓库内可直接复现；`--section` 按册子实际节数给——十节册用 10，起步骨架只有 3 节）：

```bash
python scripts/run_all.py "assets/样例-12-路径与轨道词汇册.html" --section 10 --deny-file "scripts/deny-sample.txt"
python scripts/run_all.py "booklets/03-版式与组件词汇册.html" --section 3 --deny-file "scripts/deny-sample.txt" --target-dir "booklets"
```

**三条使用常识**：

- 页面有晚渲染的内容（动画结束才出现的块）时，把 `--wait` 加到 2000；
- `check_js.py` 只看内联脚本，`<script src>` 引的外部文件不会被查——用外链就自己 `node --check` 一遍；
- `check_style.py` 能自动判的只有 **emoji 必须为 0** 与 **圆角不许出现中间值**（只许 0 / 2px / 999px / 50%）；阴影种类、字号档数、以及"暖奶油+陶土"那类气质**只能靠眼睛**，交付前必须自己看截图，别拿脚本当免责。

外加两条人工项：`prefers-reduced-motion` 必须有静态终态；页面自己要有读数面板（没有读数就没有验收权）。

**两个脚本永远查不出、必须开页面看的坑**：① **正文裸写标签**（如 `<video>`）会被浏览器当成真元素，吞掉后半句并留一个空框，必须写成 `&lt;video&gt;`；② **假读数**——读数写死常数或用公式反算，拖动滑块、切换开关时数值不动。交付前逐个拖一遍，读数不动就按造假定。这两条已写进 `booklet.md` §四。

**第三个坑：脚本说"390 不溢出"，不代表窄屏能读**。表格没包 `.tw`（或长 `mono` 路径没开 `overflow-wrap:anywhere`）时，`check_overflow.py` 仍可能报 ok，但五列表已被压成"一字一行"、长路径撑出半屏。所以窄屏必须截图看，别只看 PASS。

**读数三态不许崩（脚本查不出，必须自己跑一遍）**：

1. **首帧**：演示一加载就该在终态或明确的起点，不许一进页面就横穿半屏，读数写成"误差 498px"；
2. **窗口 resize**：窗口拉宽拉窄后读数不许跳到不可能的值——临界阻尼弹簧的过冲永远是 0%，出现 `1536.3%` 说明百分比分母用了 1px 的默认值；演示状态要么重播、要么直接落终态（`20 / 20` 不许停在 `12 / 20`）；
3. 读数格式统一带单位与取舍（`0.51 s`、`34%`、`498 px`），同一页不许混用。

## 七、页面硬约束（每条都有代价）

1. **单文件自包含**：CSS/JS 内联，原生 JS，不引框架；
2. **零 emoji**（含图标位的 emoji），图标用内联 SVG；
3. **字体自托管**（`miaoda.feishu.cn` 的 css2 链接）且必带系统 fallback；
4. **表格 `table-layout:fixed` + `colgroup` 显式列宽**，且每张表外包一层 `.tw{overflow-x:auto}`（≤700px 时 `.tw table{min-width:600px}`）：桌面靠列宽不撑破页面，窄屏靠容器横滑不变"一字一行"；
5. **顶部导航不用 `position:fixed`**；多列 grid 不用 `auto-fill`；Flex 子项 `min-width:0`；
6. **viewport 带 `width=device-width,initial-scale=1`**，禁 `maximum-scale`、`user-scalable`。

**什么时候可以破例上库（只有这三种）**：

- **需要时间线**：多段动画共用一条时间轴、要 `seek()` 回放、要"中途打断后从当前位置接续"→ 上 GSAP（或 anime 轻量替代）；
- **需要滚动擦洗且跨浏览器一致**：CSS scroll-timeline 支持不足时 → GSAP ScrollTrigger + Lenis；
- **需要 3D / 着色器**：→ Three.js / R3F，且必须写降级。

其余一律原生：滚动显隐用 `IntersectionObserver`，沿路径跑用 `getPointAtLength` 或 `offset-path`，不用引库换一行代码。上库前先看 `references/sources.md` 的许可列，无 LICENSE 的不进商用产出（该文件目前只是空骨架，见 §九：查不到条目就直接说没建，不许凭印象报仓库名）。

## 十、项目里的隐私处置（写页面时遇到个人信息）

做页面时看到用户的姓名、邮箱、手机号、学校、公司、照片、客户名、聊天截图，按这四步走，**默认不写、先问**：

1. **先停手**：不把这条写进页面，也不自作主张"帮你脱敏改名"——脱敏也是改动用户内容，要先说。
2. **一句话问清**：这条要不要写进页面？给两个现成选项——（A）留占位 `[姓名]`；（B）用中性统称（"作者""编辑部""项目组"）。**不要提议用任何具体 ID 或账号代替**，那只是把一种身份信息换成另一种。
3. **没得到明确同意 = 不写**：一律用占位，并在交付时点明"这一处是占位，等你确认"。
4. **同意后才写**：写入时在该页留一行注释标记来源与同意状态（如 `<!-- 个人信息：经用户同意 -->`），方便日后撤回。

`check_privacy.py` 除了扫 Skill 目录，也可以指向**项目目录**：命中就停下来提醒用户，而不是静默通过。
