路径 ／ PATH ／ ORBIT

让一个点沿一条线走，
先得把这条线量成一串数。

前十一册说的都是「怎么变」——缓动是查表、弹簧是解方程、群体是规则。这一册换了个问题：往哪走。不是从 A 到 B 的一条直线，而是一条你自己画的曲线；画完还不算，得把它量出长度、算出切线，那个点才能匀速地、朝着正确的方向走过去。

01 / TWO BEZIERS

两个贝塞尔，压在两条不同的轴上

同一个名字，在 CSS 里指的是两样东西。分不清，你写的提示词就会把 AI 带到错误的轴上：让它做一条曲线，它给你一个缓动；让它改缓动，它去改路径。

计时贝塞尔
TIMING BEZIER
就是 cubic-bezier(x1,y1,x2,y2)。四个数是两个控制点，起点被钉死在 (0,0)、终点钉死在 (1,1)。它只压一根轴：时间——把「过了多久」换算成「走了多少」。因为要当函数用，横轴被限制在 0–1，不许倒退。
轴：时间
点数：2 个控制点
几何贝塞尔
GEOMETRIC BEZIER
就是 SVG 里的 M … C x1 y1 x2 y2 x y。四个点是空间坐标，起点终点随便放，横轴也不受限。它压的是坐标——给你一个数，还你一个点。曲线本身、圆角、图标轮廓、光点跑道，都是它。
轴：坐标
点数：2 控制 + 2 端点
一处分岔
WHERE THEY SPLIT
两者的式子是同一个（三次多项式），区别只在把什么当自变量：计时贝塞尔喂时间、出进度；几何贝塞尔喂一个比例、出一个坐标。所以别拿同一个词去要两样东西——说「要一条贝塞尔曲线」，AI 可能给你缓动，也可能给你路径。
同源
不同轴

一句话分清：问「快了还是慢了」，那是计时贝塞尔；问「它在哪儿」，那是几何贝塞尔。一条路径要跑得好看，两个都得给——路径决定它走哪，速度决定它怎么走，别指望一个 cubic-bezier 把两件事一起办了。

02 / FOUR POINTS

四个点，一条线，长度得自己量

画一条曲线很容易，让它跑得对不容易。所有麻烦都从这一句开始：贝塞尔的「进度」不是「长度」。你给 0.5，它给的是参数上的中点，不是走了一半的距离。

起点与终点
ENDPOINTS · P0 / P3
曲线一定经过这两个点，控制点一定不经过。这是判断「看错图」最快的办法：一条线如果穿过了控制点，它画的就不是这条曲线。
一定能到
设计稿的把手

2 个（三次）
1 个（二次）
二次贝塞尔
QUADRATIC · Q

03 / THREE WAYS

三种跑法，拿到的东西不一样

同一个「让点沿线走」，前端有三条路。它们都能让东西动起来，但你手里握住的数据不同：有的能给出精确坐标、有的连坐标都不给你，只知道「进度到哪了」。选错，后面全是补丁。

手段一行写法你能拿到代价
SVG 取点 el.getPointAtLength(s) 精确的坐标；切线要自己取前后两点差分。想画拖尾、想沿线发粒子、想算碰撞，都从这儿出发。 每帧在主线程算，几十个点就开始吃帧；路径一改，长度缓存要重算。
CSS 偏移 offset-path:path(…)
offset-distance:40%		 位置 + 朝向（offset-rotate:auto）。一行 CSS，浏览器丢给合成器，最省。 拿不到当前坐标，中途要发射什么东西就得另算；路径也不能随手改了再动画。
anime v4 createMotionPath(path) 返回 translateX / translateY / rotate 三条曲线，直接当 tween 属性用。 多一个库；rotate 是前后两点差分算的 atan2，转向快但不解析。
GSAP motionPath:{path, autoRotate:true} 位置、旋转、缓动、start / end 截取一段路径，全都现成。 大约 30KB 起；站在 Canvas 上还得自己换算坐标系。
四条路用的是同一条 SVG 路径当跑道；差别只在「谁在算」。能引一行就不抄仓库——先问清楚要坐标还是要朝向。

最省事的一句：只是让一个点沿线跑、还要能自动转向，就用 offset-path。要拖尾、要沿线发粒子、要读完坐标再做判断，才上 getPointAtLength。库是用来省时间的，不是用来替代理解的。

它们有一个共同点，也是最容易被忽略的一点：「进度」全都是弧长百分比，不是贝塞尔参数。这正是「跑得匀不匀」的唯一开关，单开一节讲它。

04 / ARC LENGTH

匀速只有一种写法，其余都是错觉

让 u 从 0 线性走到 1，点看着会忽快忽慢。这不是错觉：贝塞尔是参数方程，u 每进一小步，实际走过的长度由曲率决定。这条 S 跑道两端是弯、中段是直，于是起步和收尾慢、中段快——实测 0.60×–1.21×，同一个 u 步长，最慢处只走到最快处的一半。想让点匀速，只能把「u」换成「已走长度 ÷ 总长」。

红点按参数 u 走 · 黑点按弧长 s 走 · 灰点是 10 等分的弧长刻度

拖尾是最先暴露问题的地方：按 u 排放，弯处挤成一坨、直处拉得很开，看着像「加速冲过去」；按 s 排放，间距才均匀，才像一条尾巴。CSS 的 offset-distance 天生按弧长，所以它反而比你手写贝塞尔更匀——代价是你拿不到当前 u。

再补一句常被混掉的：匀速 ≠ 线性。匀速是「长度随时间是直线」，线性是「进度随时间是直线」。你完全可以在弧长上再套一层缓动（先慢后快），那还是沿路径跑，只是不匀速——两层要分开调，别一个按钮全改。

05 / TANGENT

朝向要么算出来，要么就一直错

一个方块沿线跑却不转向，看着不像在轨道上跑，像被一台固定摄像机拍着平移——弯的地方尤其假。朝向就是切线角：沿路径取这个点前后一丁点两个位置，相减，atan2(dy, dx)。库里都这么干，快，但在尖角处会跳一下。

切线角
TANGENT ANGLE
不用背公式，只记一件事：切线是「往哪走」，不是「在哪」。取 s−ε 与 s+ε 两点求 atan2；ε 越小越准、也越容易被浮点数咬，经验上取总长的 0.5% 就稳。
atan2(dy, dx)
单位：度

CSS 的 offset-rotate:auto、GSAP 的 autoRotate:true，开了就不用自己算。想要「永远竖着」就写 auto 90deg，省得在代码里补角度。

写提示词时的差别：只说「沿曲线运动」，AI 有八成不给你转向；说「auto-orient / offset-rotate:auto，物体中心对齐路径」，它才知道你要的是「贴着轨道跑」，不是「路过一条线」。转向是独立的一项，不是路径的附属品。

06 / PULSE & TRAIL

脉冲和拖尾，靠错峰活着

一条线上跑一个光点，读起来是「加载中」；三条线上各跑两个、相位彼此错开，才像「系统正在运转」。这类效果真正只有一个参数：相位差。错了，全场同步，一眼假。

脉冲
PULSE
一个短促的点或一小段亮线沿路径跑，到端点淡出。用 sin(u·π) 让两头淡——不然它会在起点凭空出现、在终点凭空消失，像一张贴图。
u = (t·speed + seed) % 1
seed 错峰
SEED OFFSET
每条线、每个脉冲加不同的起始偏移。同一个 seed 用两次，那两个点会永远重叠——看着像只有一个点在闪。
每条边不同 seed
不要复用

不是一条线，是最近 N 帧位置的数组。间距要按弧长取（上一节的 s），按 u 取就会在弯处糊成一团。
N 帧历史

为什么「同相位」一眼假：六个点会在同一帧齐刷刷亮起、齐刷刷消失，读起来是一个开关，不是六条线在工作。真实系统里没有两件事同时发生——这一条比任何缓动都更像真的。

07 / CLOSED LOOP

接缝是最容易露馅的一格

把路径首尾接上就成了循环。麻烦在接缝：位置接上了，切线不一定接上。两端切线角不一样，光点跑到那儿会「顿」一下，像换了一个东西在跑。

Z 收口
CLOSE PATH
SVG 里写 Z 会从当前点补一条直线回起点。所以想要曲线闭合，最后一段的终点必须正好落在起点上，否则白得一根直线。
Z = 直线
不是弧
切线连续
C1 CONTINUITY
两段相接处，共用那个控制点必须和接点共线，角度才不会突变。做环形轨道时最省的做法，是把控制点按 3 的倍数摆一圈。
共线 = 平滑
不共线 = 折角
周期对齐
PERIOD SYNC
一圈时长要能被脉冲个数整除，否则回到起点会出现「跳格」。3 个脉冲、一圈 2.4s，相位步长就是 0.8s——不是随手写 0.7。
T / n = 相位步长
时间取模
MODULO, NOT RESTART
循环不要用「每圈重启动画」，那会把相位每圈清零，中途改速度就错位。对时间取模，改速度也接着跑。
(t % T) / T

还有一个更隐蔽的：闭合路径的起点在弧长表里是同一个位置，但你可能两端各取了一次点，接缝处就重复一帧——表现出来是光点在起点闪一下。解决：循环区间写 [0, L)，不含 L。

09 / THE PROMPT

五槽位：这一次第二槽要写「按弧长还是按参数」

说「沿曲线动」等于没说——AI 会给你一条路径，再配一个它顺手的缓动，速度从头到尾是它猜的。把取点方式写进第二槽，这条曲线才归你管。

1
对象与路径
谁在动、沿哪条线。把 d 的四个点说出来，或者说出「起点、终点、两个控制点的方向」。只说「一条弧线」，它给你一条随手画的。
3 条连线
各 2 个 6px 点
2
取点方式
这一槽是本册的关键：写 按弧长 s 还是 按参数 u，或者直接点名 getPointAtLength / offset-path。不写，速度就是它猜的。
getPointAtLength
s = (t·speed+seed)%L
3
速度
匀速、某个缓动名、还是物理。匀速就写「线性，不进缓动」；别让 AI 一边沿路径跑一边又套 cubic-bezier，那两件事会互相抵消。
一圈 2.4s · 匀速
4
朝向
不转、贴切线、还是插值。auto-orient 一句话能省掉一堆代码；圆点可以不转，箭头不转就废了。
auto-orient
或「不旋转」
5
验收
这一槽给数字：相位跨度、端点亮起数量、单帧跳变上限、reduced-motion 停在哪。有了数字，你才有权说「不对」。
相位 ≥ 60%
跳变 < 20°
可直接复制 · 只改对象与数字即可
  • 做一个「数据在三条连线上流动」的提示动效。三条三点贝塞尔连线，两端是模块边框，线略微外鼓。
  • 对象与路径：每条线上 2 个 6px 圆点，沿路径跑；线宽 1px，颜色跟模块同色系。
  • 取点方式：用 getPointAtLength，s = (t·speed + seed) % L，按弧长取点，不要按贝塞尔参数 u。
  • 速度：一圈 2.4s 匀速，线性推进，不叠缓动；speed 给一个 0.8–1.6 的可调参数。
  • 朝向：圆点不旋转；如果把圆点换成箭头，要 auto-orient 贴切线并让中心对齐路径。
  • 淡出：首尾各 10% 用 sin(u·π) 淡入淡出，不要硬切、不要用透明度曲线再拖一段。
  • 错峰：6 个点 6 个 seed，相位跨度 ≥ 60%，任意时刻不允许两点重叠；不要同相位。
  • 验收：改速度后相位不乱；reduced-motion 时静态停在 50% 位置、六个点均匀分布；单帧角度跳变 < 20°。

这一册的第二槽为什么不是「时长」：沿路径跑的时长由「路径长度 ÷ 速度」决定，你写死的每一秒都会被路径长度出卖。给速度，别给时长——这跟第十一册给 ζ、不给时长是同一条道理。

10 / THE EDGES

四条边界，都是踩过的

ED 01
别让正文沿路径跑
textPath 只适合徽章、环形标语、一两行的印章。正文跟着曲线拐，读到第三行就得歪脖子。字要读，就别让它拐弯。
ED 02
路径动画不是物理
沿路径跑的东西不受重力、摩擦、碰撞影响；它只是按时刻表到达坐标。要「掉下来弹两下再停」，那是第十一册的物理世界，不是这一条线。
ED 03
路径越长、越贵
每帧 getPointAtLength 都在主线程上查表，20 个追随点就能吃到帧。要几十上百个点，先预采样成数组，或者搬去 canvas 一次画完。
ED 04
一个页面只留一处「巡线」
沿着线跑的光点是氛围，不承载信息。它在两处出现是「系统在运转」，在十处出现是「屏幕在抽搐」。把它留给那一条你最想让人看的线。
