# 拆解规格（主线 A）

> 拆解不是写观后感。拆解的产物必须是**可复用的词 + 可报的数 + 可复刻的一行路径**。
> 判断标准只有一句：**别人拿着这份拆解，能不能不看你，自己复刻出来。**

---

## 一、三种输入，三种代价

| 输入 | 能拿到什么 | 拿不到什么 | 必须先做 |
|---|---|---|---|
| 本地仓库 | 源码、依赖、真实参数 | 跑起来的观感 | 看 LICENSE，再跑一次 |
| 线上站点 | 渲染结果、CSS 变量、网络请求里的库名 | 源码与真实意图 | 记录版本与抓取日期 |
| 视频 / 截图 | 动效顺序、节奏、层次 | 参数、库名、实现方式 | 只能给"估"，不许标"实测" |

**铁律**：`实测` 与 `估` 必须分栏标。视频来源的参数一律写"估"，并注明"按 x 帧/秒推算"。

---

## 一·补、视觉风格（visual style／VS）（六栏之前先写这一块，五行固定）

只收参数会丢掉最容易复用的那一半：**这个项目整体长什么样**。名字叫风格，填的却是五项**值**——不是"科技风""极简风"这类流派标签，也不是形容词。

| 行 | 写什么 | 反例 |
|---|---|---|
| 判定 | 一句话说清它属于哪种视觉风格，带三个锚：底色性质 + 光源数 + 强调色数（例：单光源暗场图谱面板） | "很有科技感" |
| 底色与色域 | 底 / 面板 / 线三层的具体色值；强调色 ≤2，各管什么（一色管数据、一色管连接） | "深色系，看着很舒服" |
| 光源与材质 | 光从哪来（素材自发光 / 顶部聚光 / 无光）；层次靠什么做（1px 线 + 透明度 / 阴影 / 模糊） | "质感很高级" |
| 字与形 | 标题、正文、数字三类字的字体关系；字号几档；圆角取值；信息密度 | "排版很讲究" |
| 可搬 / 别搬 | 三条可直接搬的（如单光源暗场、双强调色分工、1px 线替代阴影）+ 一条明确别搬的（具体素材、品牌字标、要授权商用的字体） | 只写"值得学习" |

**为什么放在六栏之前**：读者先有画面，后面的参数才知道落在哪；反过来，先读到 `k=62` 只是一个数字。

三条纪律照旧：不许形容词交差；查不到写 `未见`；**视觉风格的元素也要过许可**——色值、字阶、光比可搬，字体文件与素材不可搬。

可搬的三条不是写给自己看的：每条都要在 `booklets/风格元素.md` 落一行（元素 / 出处 / 适用场景 / 反例），跨项目累积成选风格时的参考库。

---

## 二、六栏固定输出（顺序不许换，前面先有「一·补 视觉风格」）

1. **来源与许可**：项目名 / 链接 / 抓取日期 / LICENSE（没有就写 `unknown`，不许省略）。
2. **骨架与分层**：用了什么框架、几个库、页面分几层（背景 / 中景 / 前景 / 浮层 / 交互层）。
2·补. **模块全量清单**（不许省）：这个产品**有几个模块就列几个**，一个不落，名字用**它自己的官方名字**（组件用设计规范的正式名，如 `Bottom sheet`／`Split Button`；工具面板用它代码里的面板名）。每个模块一行：官方名 / 归属（画布侧组件 or 工具侧面板）/ 它负责什么 / 代码入口（文件:行号）。用户数得出 11 个模块，稿子里只有 8 个，这份拆解就作废——**"没那么多"才允许少，凑不出就是没拆完**。
3. **动效清单**：一条一行 = 中英名 | 参数区间 | 实现代价（主线程 / 合成器 / 要库 / 拿不到坐标）| 实测或估。
4. **它认得的词**：对到 `words.md` 的**册号 + 轴**（例：`几何贝塞尔（12）`、`错峰（10）`）。
5. **它不认得的词**：新词进"待验"，必须带三问答案（在哪验过 / 参数区间 / 验收数字），答不全就留在待验。
6. **最小复刻方案**：不抄代码，只给一行路径——"用 `getPointAtLength` 取点 + `sin(u·π)` 淡出，30 行以内"。

**第 2·补 与第 3 的分工**：模块清单回答"这东西由哪些件组成"，动效清单回答"这些件动起来靠什么"。两栏都全量，一册只取一轴。

---

## 三、三条纪律

- **不许用形容词交差**："高级、丝滑、有呼吸感"出现在报告里，等于这一栏没写。
- **不许把"没看到"写成"没有"**：区分"我查不到"与"它不存在"，前者写 `未见`，后者才写 `无`。
- **代码只引用不搬运**：给了路径与行号，不整段贴。无 LICENSE 的项目连片段都不进商用产出。
- **术语以官方为准，自造要标**：模块名、组件名、交互名优先用设计规范或代码里的正式叫法；官方没有对应词时才自拟，并在括号里写"本稿命名"，别让自拟词混进词库冒充标准词。

---

## 四、什么时候立新册

先分清两件事：**拆解是全量的，册子是有取舍的。** 拆解稿按项目实际模块逐个写（第 2·补），不裁剪；册子是给"要学名词的人"的一本小书，只讲一条轴上的十二个词。

立册的门槛（只管册子选题，不管拆解深度）：

- 这条轴上能凑出 **≥6 个可命名对象**，且这些对象之间有**能讲清的层级关系**（不是六个并列的小技巧）；
- 能给出 **≥1 条"容易错的地方"**（如果没有，说明还没拆到底，只看到表面）；
- 能写出 **四条边界**（什么时候别用）。

三条不全 → 不立册，把该轴的词并进已有册的 §08 速查表。**未立册 ≠ 未拆**：剩下的模块原样留在拆解稿里，等第二条轴攒够再立。

---

## 五、拆解的收尾（两个动作，缺一不算完）

1. **回填 `words.md`**：新词先入"待验"，**同一词在第二次拆解里再出现才转正**——单次出现很可能只是那个项目的个人癖好。
2. **回填 `sources.md`**：一行指针（名字 / 类型 / 许可 / 它独有什么 / 看哪里 / 什么任务才去看）。
3. **写「未上册清单」**：全量模块清单里，哪些没进册子、为什么（属"只是存在"档）、以后要进该落在哪一节、还缺什么。`booklet.md` §九 的增量扩展只认这份清单。

拆解不落库，等于白拆。

---

## 六、六栏 → 一册（十节怎么长出来）

拆解稿是给"要动手的人"看的，册子是给"要学名词的人"看的。两者是同一份分析的两种排版：

| 六栏 / 十节 | 内容去向 |
|---|---|
| 视觉风格（一·补，VS） | 册子头部「视觉风格」块（5 行，不占节数；见 `booklet.md`） |
| 骨架与分层 | §01（分轴）+ §02（整体形状） |
| 动效清单（含"最容易露馅的地方"） | §02–§07，每块配一个演示或对照表 |
| 它认得的词 | §08 十二词速查（只留 12 个，多的一致性裁掉） |
| 最小复刻方案 | §09 五槽位 + 可复制提示词（4–8 行） |
| 不认得的新词 + 边界 | §10 四条边界（什么时候别用） |
| 来源与许可 | 页脚与册内一处引用，不进正文吹捧 |

**注意**：六栏里"动效清单"往往十几条，一册只留 12 个词——**裁掉的不是不重要，而是不成体系**。裁下来的词进 `words.md`，不留着占版面。

## 七、落盘位置（拆完的东西放哪）

```
<项目目录>\拆解\<项目名>\
   <项目名>·拆解.md     拆解原稿（固定六栏顺序；文件名＝项目名＋"·拆解"）
   素材\                截图 / 帧序列 / 抓包
   复刻.html            可选：最小复刻实验（不进册）
<项目目录>\booklets/
   <主题>词汇册.html   成品册
   索引.md              册目 + 待拆清单 + 待验清单
```

领域线（模式 B）不落这里，另开平行目录：`<项目目录>\综述\<主题>\横评.md`（规格见 `survey.md`）。**两个目录不许混放**——拆解稿写的是"一个项目怎么做的"，横评稿写的是"一个主题有几种做法"。别再拿"六栏"当文件名，那只是结构叫法。

拆解原稿**先落盘再写册**：没有原稿的册子无法回溯参数来源，等同于一次性文章。

### 落盘自证（不做这一步 = 等于没落盘）

写完文件后，必须当场输出三样，缺一样就视为未落盘：

1. **绝对路径**（不是"拆解目录"，是 `<项目目录>\拆解\<项目名>\<项目名>·拆解.md`）；
2. **字节数**（`Get-Item` / `ls -l` 查到的真实大小，不是估计）；
3. **首行原文**（回读文件第一行，证明写进去的是预期内容）。

**禁止**用"已保存到…"这句话代替以上三样。生成一份在线文档卡片、在聊天里贴 Markdown 预览，**都不算落盘**。

**根目录只认一个**：`<项目目录>\拆解\`。源码仓库可以 clone 到别处，但六栏稿必须落在项目目录下的 `拆解\`，否则booklets与拆解会分裂成两套，`索引.md` 也对不上。
