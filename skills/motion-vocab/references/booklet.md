# 册子规格（一册 = 一个单页 HTML）

> 册子的作用只有一个：让读的人在五分钟内**能说出这个东西的名字，并且会用名词指挥 AI**。
> 它不是文章，是**词典形的展示页**：一节一个断言，一节至少一个可拖的演示。

---

## 一、硬规格（少一条就不叫册）

| 项 | 定值 |
|---|---|
| 文件 | 单个 HTML，零外部依赖，CSS/JS 内联，原生 JS |
| 节数 | 10 节（一节一个 `h2`） |
| 词条 | 12 个（第 8 节速查） |
| 槽位 | 5 个（第 9 节，含 4–8 行可复制示例） |
| 边界 | 4 条（第 10 节：什么时候别用） |
| 演示 | ≥3 个，能拖/能点，**每个带 ≥3 个读数** |
| 编号 | 册号 = `索引.md` 最大号 +1；**露三处**：文件名前缀 `NN-`、`h1` 前缀「第 NN 册 ·」、页脚（册链首格写号，或页脚上方一行 `.bkno`「第 NN 册 · 主题」） |
| 兜底 | `prefers-reduced-motion` 有静态终态 |
| 页脚 | 册链（册号 + 一句主题） |

---

## 二、十节骨架（顺序固定，内容每册不同）

| 节 | 该写什么 | 常见错误 |
|---|---|---|
| 01 | **分轴**：把两个最容易混的概念压在两条不同的轴上（如计时贝塞尔 vs 几何贝塞尔） | 一上来就讲"什么是 X"，没有对照就没有定义 |
| 02–07 | 六个可讲块，每块一个演示或一张对照表；必须有一节讲"**最容易露馅的地方**" | 六块平均用力，读完记不住任何一块 |
| 08 | 十二词速查：词 / 英 / **册号 + 轴** / 参数区间 / 用途（五列固定），表下接**弹药匣**（见 §二·补） | 只有名字，没有区间＝把 AI 又推回猜；漏了册号 + 轴，换册就撞名 |
| 09 | 五槽位 + 4–8 行可直接复制的提示词 | 给"示例"不通顺，看着像范文 |
| 10 | 四条边界：什么场景不该用这个效果 | 只讲好处，读者会在错的地方用它 |

---

## 二·补、每个词必须给三件（升级项，别漏）

一个词条只有名字等于没写。每个词都要有「术语 / 用途 / 系统提示词」三件，**而且必须长在它自己那一节的旁边，不许集中堆到末尾**。

**第一处：每节的术语卡（右侧栏，紧贴演示）**

读者看的是演示，术语就得在同一屏。做法是让演示块变两列：左列演示 + 滑块 + 读数，右列一张 336px 宽的卡，卡里四段固定：

```
术语   遮罩停点调度 / mask stop shift
轴     13 本册 · 收边轴   ← 有册号就写册号，没有就写本册
用途   不让素材硬边露出来：用遮罩实心停点收边，而不是把整张素材缩小
系统提示词 [一条可复制的完整段落 + 复制按钮]
```

- 演示有四个 → 至少给四张卡；只放表格没有演示的节（对照表类），把同一张卡放在表下、用整宽单列（`max-width:840px`），不要留到最后；
- 卡在 `≤1080px` 必须堆到演示下面，不许横向挤成两栏；
- 术语卡与 §08 的速查表**不重复职责**：卡给"完整句子"，表给"一眼能扫的区间"。

**第二处：§08 表下的弹药匣（简短版，保留）**

- 12 条，与 12 词一一对应，左列词名（等宽、强调色），右列一句话；
- 每条 **25–45 字**，含「对象 + 效果名 + 至少一个参数」；句法不许重样（"把…" / "让…" / 以对象开头 / 以验收数字开头各来几条）；
- 定位是**速查口令**，不是完整提示词：手机上想快速问一句就抄这条，要动真格就用上面的系统提示词。

**第三处：讲机制的节必须有实物，不许只给一张表**

素材、遮罩、弹簧、接缝这类"看见才懂"的机制，只有对照表等于没讲——读者会以为要自备素材。原素材不可分发时（许可不允许、或体积过大），用程序生成等价帧顶上：36 帧先在离屏 canvas 里画完，再逐帧 `drawImage` 上屏；旁边给一个"每帧都重绘 / 变了才重绘"的开关，读数放帧号、`drawImage` 每秒、累计上屏三项。这样既自证了原理（省下的那 35 次白烧是读数可见的），又把整册做成完全可分发的单文件。

**第四处：头部必须有「视觉风格」块（讲整体，不占节数）**

只讲"这一节怎么动"，读者读完不知道整屏该长什么样，也搬不走任何东西。所以在头部（`h1` + `lead` 之后、第一张 claims 之前）固定一块「视觉风格 visual style」，五行，压成一行一条：

```
判定     单光源暗场图谱面板：底色近黑、光只从素材来、强调色两组分工
底色     #0D0E0E 底 / #161717 面板 / rgba(228,228,222,.11) 线
光源     唯一光源是素材自发光；层次用 1px 线 + 透明度，不用阴影
字与形   无衬线一套 + 字号 9–40px 十几档；圆角 16px / 999px / 50%
可搬     单光源暗场 · 一色一类的标识色 · 1px 线替代投影
```

- 五行都必须落成**值**（色号、档数、像素）；"科技风 / 极简风 / 高级感"一律不算数——名字叫风格，填的是值；
- 两种写法分开：**拆解册**写"这个项目不动时的底（拆自 X）"，值来自源码；**领域册**没有单一项目可拆，写"本册自己定下的底（非单项目拆解，此块写本册的取舍）"，值来自本册自己的 CSS 变量；
- 末尾那句"可搬"要写进 `booklets/风格元素.md`，一条一行：元素 / 出处 / 适用场景 / 反例；
- 这块放在头部而不是正文，是为了**不占十节**（节数由 `check_struct.py --section 10` 硬拦）。

**两处都不许新开一节**：节数固定 10（`check_struct.py --section 10` 会拦），术语卡进在演示块内，弹药匣进在 §08 内。

## 三、视觉配方（选一张纸，一个强调色，不许混）

- **纸**：网格 / 走线 / 坐标 / 暗场 / 纸感 / 纯白——六选一，且必须能回答"它为什么解释这个题材"。
- **色**：一套中性灰阶 + ≤2 强调色，强调色只落在"数据 / 当前态 / 路径"上。
- **字**：衬线标题 + 等宽数据旁注 + 无衬线正文，字号 ≤5 档。
- **形**：零圆角与统一圆角只能选一种，不许中间值（`check_style.py` 会拦）。
- **密度**：表格用 `table-layout:fixed` + `colgroup` 定桌面列宽；每张表外面必须包一层 `.tw{overflow-x:auto;max-width:100%}`，并在 `@media (max-width:700px)` 里给 `.tw table{min-width:600px}`——窄屏让表在**容器内横滑**，页面主体仍不许横溢（`check_overflow.py` 只查主体，容器内滚动不算违规）。不包这一层，390 下五列表会被压成"一字一行"：合规，但没法读。

**禁止**：五种 AI 默认视觉样式（暖奶油+陶土、近黑+酸性绿、大报式密集分栏、同款阴影圆角卡、全大写眉标+中点元信息+`→` 后缀）。

## 四、写作纪律

- **标题是断言，不是名词**：写"接缝是最容易露馅的一格"，不写"关于接缝"。
- **每节第一句回答"为什么有这一节"**，读者才知道该不该读下去。
- **数字必须能追**：实测的标"实测"，推算的标"估"，并给推算依据。禁止"通常""大约"了事。
- **不许出现**：简单 / 轻松 / 一键 / 小白也能 / 满满的高级感。
- **正文提到标签必须转义**：`<video>`、`<canvas>` 这类词一旦裸写进段落，浏览器会当成真元素，把后半句吞掉，还在版面上留一个空框（写 `&lt;video&gt;`）。`check_struct` / `check_js` / `check_style` / `check_overflow` 四项全绿也拦不住，只能打开页面读。
- **读数必须采样**：演示读数要由当次绘制或像素剖面算出来（`getImageData` 取最大 alpha 跳变、`drawImage` 每秒计数）。写死常数、或用一个不对应几何的公式反算，等于把「验收权」作废——**拖动滑块 / 切换开关后读数不动，就是假读数**。
- **一个演示只讲一件事**，两个参数以内；读数放演示下面，不要藏。

## 五、收尾（交付前必做）

1. `python scripts/run_all.py "{file}" --section 10 --deny-file "{禁词}"` 五项全绿（不传 `--deny-file` 时只跑四项，末行会写「隐私未检查」，别当成全绿；溢出项因缺 playwright 报 `SKIP` 也不算通过）；
2. 截图自己看一遍（脚本判不了配色气质）；
3. 缩到 390px 再看一遍；
4. 页脚册链更新，并回填 `words.md` 里本册新增的词。

## 六、册子与 Skill 的分工

册子是**正文**，Skill 是**目录与判据**。所以：

- 册子不进 `references/`（12 册约 60 万字节，塞进去会把上下文打满）；
- `SKILL.md` 只写路径与"什么任务读哪册"；
- 每册交付后，只需在 `words.md` 增一行覆盖说明——不动 `SKILL.md`。

---

## 七、读者是谁（决定了用多少行讲同一件事）

每册开工前先定**主读者**，只服务一档：

| 读者 | 特征 | 这一册怎么迁就他 |
|---|---|---|
| 甲 · 完全没做过 | 不知道有这个词，也说不出想要什么 | 每个名词都必须配一个**能拖的演示**；术语第一次出现要给英文 |
| 乙 · 做过但说不出 | 见过效果，只会说"就那种""像水一样" | 重点是**对照与命名**：同一现象的 2–3 个叫法摆在一节里挑 |
| 丙 · 说得出但说不准 | 知道名字，参数靠猜 | 重点是**区间与代价**：读数、实测值、不同实现的差别 |

判法：读者说不清"我想要什么"→ 甲；说得出效果但叫不出名 → 乙；报得出名但报不出数 → 丙。**一册只服务一档**，混着写会两头都不够。

## 八、落盘与命名

```
<项目目录>\booklets/<主题>词汇册.html            成品
<项目目录>\booklets/索引.md                      册目 + 待拆清单 + 待验清单
<项目目录>\拆解\<项目名>\<项目名>·拆解.md     拆解原稿（先有原稿，才有册）
<项目目录>\综述\<主题>\横评.md               领域线原稿（横评七段）
```

- 文件名 = `NN-主题.html`（`16-响应词汇册.html`）：**编号是前缀，主题不能省**；不许叫 `index.html`，不许只写 `16.html`、`第16册.html`；
- 同一册号必须同时出现在文件名、`h1`、页脚（册链首格或 `.bkno` 行）三处，读者一眼能对上索引；
- 拆解原稿**不许再叫 `六栏.md`**：名字里要带项目名，一眼知道这是拆谁；
- 编号只由 `索引.md` 分配，最大号 +1、空号不补；引别册（§08 表、页脚册链）用同一套号，不许另起一套；
- 交付后回来补三行：索引加一行、`words.md` 加覆盖说明、页脚末格改成本册。

## 九、从全量拆解里选料（册子不必做全，但要说清没做哪些）

拆解稿是母本（`teardown.md` §二 2·补：项目有几个模块就写几个）；册子是选本，只挑少数值得教的，剩下的留在原稿。

选料三档，按 A → B 排：

| 档 | 判据 | 去向 |
|---|---|---|
| A 独特且亮眼 | 别处没见过，或见过但没人讲清；掏出参数就能立刻用 | 必上，进 §02–07 的主块 |
| B 通用但讲得最清楚 | 大家都在用（弹簧、错峰、贝塞尔），但这个项目给了可报的数 | 上，作为对照或一行区间，不单独占节 |
| C 只是存在 | 有，但没有可报的数、也没有独特做法（图标选择器、骨架屏这类） | 不上册，进「未上册清单」 |

一册只装 12 词，装不下不许硬塞。挑完必须做一件事：在拆解稿末尾写「未上册清单」，一行一个：模块名 / 为什么没上（属 C 档）/ 若以后要上它落在哪一节 / 还缺什么（演示？参数？第二来源？）。这份清单是以后扩展的唯一入口。

允许增量扩展同一册（v1.x），四条规则：

1. 用户说「把 XX 也加进去」→ 只从该项目的「未上册清单」里取，不临时另找素材；
2. 加词只能进已有的十个节：进 §02–07 的某个块，或进 §08 速查＋弹药匣，不许新开一节（`check_struct.py --section 10` 拦）；
3. 每加 1 词同步改四处：§08 表、弹药匣、页脚版本号（`v1` → `v1.1`）、`words.md` 覆盖说明；
4. 加到 16 词以上停手并提醒：再长会把「十二词速查」变成词表，该换一条轴拆第二册，而不是继续长胖。

版本号写页脚：`v1` = 交付时的 12 词；`v1.1` = 从同一份拆解稿里补了词，不是重做。
