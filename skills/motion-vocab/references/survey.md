# 领域线规格（模式 B）：一个主题的横评

> 与拆解线的区别只有一句：**拆解是"一个项目怎么做成的"，领域是"同一件事有几种做法、哪种在什么条件下更划算"。**
> 拆解有源码兜底，领域没有——所以领域的全部风险在取证上，规格也就是为取证写的。

---

## 一、什么时候走这条线

| 用户说的话 | 走 |
|---|---|
| "拆这个项目 / 这个站点 / 这条视频" | 不走这条，走 `teardown.md` 的拆解线 |
| "我想了解 **滚动驱动** 这块有哪些做法 / 有哪些案例 / 该怎么选" | 走这条 |
| "**版式 / 纵深 / 风格 / 鼠标 / 编排 / 群体**这类有哪些套路" | 走这条 |
| "给我做个页面" | 都不走，走设计线（`intent.md` + `words.md`） |

**判断依据**：用户给的是**别人的东西**（有具体对象）→ 拆解线；给的是**一个主题词**（没有具体对象）→ 领域线。

**领域线不是"凭经验总结"**。它和拆解线一样要落盘、要取证、要给数——只是取证的形状从"源码行号"变成"多个可核来源的对照"。

---

## 二、四条硬门槛（少一条就不立册）

1. **≥5 个可核来源**：每个都要能打开或能下载（仓库 / 站点 / 库文档），带**访问日期**；不许出现"很多网站都这么做"。
2. **≥2 个真分歧点**：同一个目标，两派做法在参数或代价上真的不一样（例：CSS `scroll-timeline` 与 GSAP ScrollTrigger + Lenis，差在跨浏览器、`seek()` 能力、包体积）。
3. **≥1 个案例当场跑通**：本地起得来、或线上能打开并读到实际值。做不到就整册降到"待验清单"，不立册。
4. **许可逐条记**：每个来源的 LICENSE 写清（`MIT` / `Apache-2.0` / 无 / 私有）。无许可的只能当参考书，参数可搬、素材与代码不搬。

凑不齐 → 不立册，把已有条目进 `booklets/索引.md` 的"待验清单"，标注缺哪几条。

---

## 三、产物：横评稿（固定七段，顺序不许换）

落盘 `<项目目录>\综述\<主题>\横评.md`，素材进同级 `素材\`。

| 段 | 内容 | 判它合格的问法 |
|---|---|---|
| 1 主题与边界 | 这个主题**包含什么、不包含什么**（例："滚动驱动"含擦洗 / 钉住 / 映射，不含"滚动到某处触发一次"） | 边界不清，后面全是混说 |
| 2 分野 | 2–3 派做法，各一句话说明"它认为这件事的本质是什么" | 两派答的是同一个问题吗 |
| 3 横评表 | 每行一个案例：来源 / 许可 / 日期 / 参数区间 / 实现代价 / 它独有什么 | 能不能点开核实 |
| 4 分歧点 | ≥2 条：同一目标下两派差在哪，**差多少**（给数字） | 有没有"差在……"后面接数字 |
| 5 收敛区间 | 跨案例取出的建议值（这是领域册最值钱的一格：单项目给不出） | 这个区间是从表里算出来的，还是拍出来的 |
| 6 反例与边界 | 4 条：什么题材 / 什么预算下别用这套 | 有没有"看情况"这种糊话 |
| 7 来源指针 | 每个案例一行：名字 / 类型 / 许可 / 看哪里 / 什么任务才值得看 | 能不能照这一行找回原处 |

**铁律**：第 3 段的每一行都必须能追到第 7 段的指针；第 5 段的区间必须能由第 3 段算出来。**追不到的行删掉，不许留着好看。**

## 四、从横评稿到册（十节怎么长）

骨架仍用 `booklet.md` 的十节，但三处换掉：

| 节 | 拆解线 | 领域线（这条） |
|---|---|---|
| 01 | 分轴：两个易混概念压到两条轴 | **分野**：这个主题下有哪几派，各自主张什么 |
| 02–07 | 一个项目的六个实现块 | 每块讲**一派做法 + 一个对照表**，块内必须有跨案例数字 |
| 08 | 十二词速查（词 / 英 / 册号轴 / 区间 / 用途） | **十二个可迁移参数**（参数 / 谁在用 / 建议区间 / 代价） |
| 09–10 | 五槽位 / 四条边界 | 不变 |
| 页脚 | 单项目的许可 | **每个来源一条许可 + 访问日期**，缺一行不合格 |

视觉与术语卡的要求与拆解线完全一致：每个演示旁挂"术语 / 用途 / 系统提示词"卡（见 `booklet.md` 二·补）。

---

## 五、四种退化样式（出现即返工）

1. **百科罗列**：五段各介绍一个网站，读完不知道该用哪个 → 缺第 2、4 段。
2. **只报名字不报数**：写"GSAP 的 scrub 很顺"却不给 `scrub: 0.5–1`、不给包体积 → 第 3 段每行必须带数字。
3. **把单项目当领域**：只拆了一个项目就下结论"这就是行业做法" → 第 1 段边界没划，第 3 段不够 5 行。
4. **拿不到证据就编**：写"业界普遍认为" → 直接删该行，降级到待验清单。

## 六、落盘与命名

```
<项目目录>\综述\<主题>\横评.md     领域原稿（七段固定）
<项目目录>\综述\<主题>\素材\       截图 / 抓包
<项目目录>\booklets/<主题>词汇册.html  成品册
<项目目录>\booklets/索引.md            册目（"来源类型"列写 领域）
```

- 原稿文件名 = `横评.md`，放在主题目录里，**不要**出现"第几册""六栏"这类内部叫法；
- 册子名取主题名词（`滚动驱动词汇册`），不带编号、不带"综述"二字；
- 交付后回填三处：索引加一行（来源类型写"领域"）、`words.md` 加覆盖说明、页脚来源许可证。
